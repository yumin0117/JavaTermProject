# 실행 테스트 순서

1. 외부 설정을 입력하고 Oracle 테이블/시퀀스를 준비한 뒤 App을 실행한다. 설정을 비운 상태로 로그인하면 접속 정보 입력 안내가 나오는지 확인한다.
2. 새 계정 만들기에서 아이디·비밀번호·확인·닉네임·이메일을 입력한다. 빈 필수값, 31자 아이디, 비밀번호 확인 불일치와 중복 아이디를 각각 확인한다. 정상 가입 후 로그인 화면으로 돌아간다.
3. 잘못된 비밀번호는 실패하고, 새 계정의 올바른 비밀번호는 로그인된다. 기존 user01의 DEMO 문자열로 로그인할 수 없어야 한다.
4. 내 플레이리스트에서 ‘새 플레이리스트’를 눌러 제목과 설명을 작성한다. 기본값 비공개로 생성한 목록이 보이는지 확인한다.
5. 목록을 선택하고 ‘수정’으로 제목·설명·공개 여부를 변경한다. 새로고침 후 DB의 수정 결과가 유지되는지 확인한다.
6. ‘상세 보기 / 곡 관리’에서 ‘네온’으로 검색한다. ‘별빛 산책’의 참여자가 루나, 네온 모두 표시되는지 확인한다. 제목 ‘푸른’으로도 검색한다.
7. 곡 3개를 차례로 추가한다. 추가 순서가 1·2·3인지, 같은 곡 재추가가 차단되는지 확인한다.
8. 수록곡을 선택해 위로·아래로 이동한다. 1번의 위로, 마지막의 아래로 이동은 변화가 없어야 한다. 이동 후 새로고침해 순서가 유지되는지 확인한다.
9. 중간 곡을 제거한다. 남은 순서가 1·2로 정리되는지 확인한다. 검색에서 제거한 곡 원본을 다시 찾을 수 있어야 한다.
10. 공개 플레이리스트 탭에서 제목으로 검색하고 다른 회원의 공개 목록 상세를 연다. 읽을 수 있지만 곡 추가/제거/순서 버튼은 없어야 한다. 좋아요가 0인 목록도 검색된다.
11. 좋아요를 등록하고 취소한다. 수와 본인 상태가 갱신되어야 한다. 자기 공개 목록에도 좋아요를 누를 수 있다.
12. 다른 새 계정으로 로그인한다. 첫 계정의 비공개 목록은 안 보여야 한다. 첫 계정에서 공개로 바꾸면 보이며, 두 번째 계정에서도 수정은 불가하다.
13. 첫 계정으로 돌아와 테스트 목록을 삭제한다. 확인창에서 아니요를 누르면 유지되고, 예를 누르면 목록·수록곡 연결·좋아요만 삭제된다. 곡·아티스트·회원 원본은 남는다.
14. 로그아웃하면 로그인 화면으로 돌아간다. 계정을 바꿨을 때 이전 계정의 내 목록과 상태가 남지 않아야 한다.

자동 검증: `mvn clean package`, 실제 DB 검증: `mvn -Poracle-test test`. 권한을 우회한 번호 직접 조회와 다중 연결 동시 수정은 OracleIntegrationTest에서 서비스 호출로 확인한다.
